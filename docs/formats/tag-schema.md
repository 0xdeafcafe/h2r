# Tag layout schemas (`tags::schema`)

Status: **Built** (2026-11-17) for inference, relocation and the offline
proof. **Not yet loaded by the game** (see "Load test"). Evidence labels are
those of [map-format.md](map-format.md): **V** checked on the owner's disc
and map pack, **Design** an implementation choice.

A converted Halo 1 map is going to be built fresh from an assembled tag set
rather than by pinning a retail base map ([map-builder.md](map-builder.md),
"The model"). Any retail tag that goes into such a set, or moves within one,
has to be laid out at a new address. That only works when every
layout-dependent field in it is known: tag blocks and data references
(`{count, address}`), tag references (`{group, datum}`), bare datums and
string IDs. Raw-resource pointers stay where they are for now (see "Open").

The retail XBE has no tag field definitions (field-name strings are
absent), so the layouts are **inferred from data**: every instance of
every group in every retail map. No community definition files are used.
Assembly's plugins and similar files could be used later to cross-check
the result, but nothing has been copied from them.

## The schema

`crates/tags/src/schema/layouts.txt` holds, per group, the root element
size and every layout-dependent field, with child layouts nested by
indentation. It contains offsets and sizes only, generated by the
inference below:

```text
group bitm 0x4c align 4
  0x3c block 0x3c align 4
    0x34 block 0x20 align 4
  0x44 block 0x74 align 4
```

A field line is `<offset> block <element size> align <n>`,
`<offset> tagref`, `<offset> datum` or `<offset> string`. A data reference
is a block of 1-byte elements with no fields. Groups whose name has a space
or an unprintable byte are written as 8 hex digits. Bytes with no field line
are copied unchanged. `Schema::builtin()` parses the checked-in file;
`Schema::parse` and `Schema::to_text` round-trip it.

## Inference (`tags::schema::infer`)

**V** facts the inference relies on, from all 39 maps (30 on the disc, 9
in the map pack):

- Every inferred field sits at a multiple of 4 in its element, and every
  block address is 4-aligned (alignments seen: 4, 8 and 16).
- **The cache compiler shares identical blocks between tags.** A tag's
  block often points into another tag's bytes, even one of another group:
  a `prt3` block points into a `shad`, `smg_ammo`'s `hlmt` into
  `battle_rifle_ammo`'s. Blocks are shared inside a tag too (two fields,
  one array).
- Some blocks hold a count with a null address (`{1, 0}` in `shad`).
- Some tags have no bytes at all (size 0); they have nothing to relocate.

For each array layout ("node"), starting at each group's root (one element
at the tag's address), using every instance in every map:

1. **Element size.** Each tag has a set of boundaries: candidate block
   targets (any 4-aligned pair `{count 1..2^20, 4-aligned address inside
   the tag}` with room for its count) plus the tag's end. An array of `c`
   elements at `a` ends before the first boundary at least `c` bytes on.
   The element size is the smallest `gap / c` over all instances.
   Alignment is the weakest seen, capped at 16.
2. **Blocks.** An offset is a block when, in every element of every
   instance, its pair is `{0, 0}`, `{n, 0}`, or `{n, address}` with the
   address inside the tag or, for ordinary metadata tags, inside any other
   tag. At least one must be non-null. The child's instances are the
   non-null pairs, found in whichever tag holds them.
3. **Tag references, string IDs, datums**, in that order on offsets not
   yet claimed. A field is accepted when every instance is null or
   resolves in its own map's tag index (group declared, datum present) or
   string table (index in range, length byte matching), and at least one
   instance resolves.

Bulk data (vertices, compressed animation) contains pairs that look like
blocks. They make element sizes too small. So inference runs in rounds:
after each round, every tag is walked with the schema so far, and the next
round's boundaries are the arrays found plus the candidates outside them.
It stops when the schema stops changing (at most 5 rounds).

Fields where the evidence is ambiguous, such as an offset that is always
zero or one that mixes pointer-like and scalar values, are left out. They
are not marked unknown in the file. A field left out is copied as bytes,
which is only safe when it holds no address. The relocation check enforces
that for each tag.

Regenerate the file (about 2 s, 0.5 GB of memory for all 39 maps):

```sh
H2_DISC=disc/halo2.iso H2_MAPPACK=disc/mappack.iso H2_SCHEMA_OUT=crates/tags/src/schema/layouts.txt \
  cargo test --release -p tags --test tag_schema infer -- --ignored --nocapture
```

## Relocation (`Relocator`, `to_built`)

```rust
use tags::schema::{Relocator, Schema, to_built};

let r = Relocator::new(Schema::builtin(), &mut map)?; // reads the metadata once
let tree: Result<map::build::Block, tags::schema::Refusal> = r.to_built(id);
let ids = r.movable(); // tags that can all move together
// one-off: tags::schema::to_built(&mut map, id)?
```

`Relocator::check(id)` walks the tag with its group's layout and refuses
(`Refusal`) unless:

- every array inside the tag lies within it, and the arrays **tile the tag
  exactly**: no overlaps (exact duplicates, i.e. shared arrays, count once)
  and no gaps other than zero padding shorter than 16 bytes
  (`Uncovered`, `Overlap`, `OutOfBounds`);
- arrays outside the tag (shared blocks) each lie within one other tag;
- **no word outside a known field holds an address** in the tag, the
  metadata region or any BSP region (`UnknownPointer`). This is what keeps
  a missed pointer from going unnoticed;
- the group has a layout (`NoSchema`), the tag has bytes (`NoData`), and it
  is in the ordinary metadata (`BspRegion`: BSP and lightmap tags move with
  their region, which this lane does not do).

`to_built` turns the tag into a `map::build::Block` tree: block and data
reference fields become `Block`/`Data` fixups, and shared arrays are
**copied** into the tag that uses them. The tree is self-contained, though
larger than the original. Tag references, datums and string IDs keep their
bytes, which stay valid in the same tag set. `schema::remap` rewrites them
for a tree moved between maps.

`movable()` returns the accepted tags, minus any tag that a staying tag
points into: every aligned word of every unaccepted tag is scanned for
addresses inside accepted tags, repeated until nothing changes. A pinned
tag's pointer into a moved tag's old bytes would otherwise break silently.

## Proof

All opt-in, reading the owner's ISOs, nothing written to disk:

```sh
H2_DISC=disc/halo2.iso H2_MAPPACK=disc/mappack.iso \
  cargo test --release -p tags --test tag_schema -- --ignored --nocapture
```

(`H2_SCHEMA_MAPS=lockout,shared` picks maps; `H2_SCHEMA_WHY=1` adds the top
refusal places per group to the coverage report; `H2_SCHEMA_PROBE=hlmt:0x5c`
prints the words around one root offset.)

**Shuffle** (`shuffle_every_relocatable_tag`), **V** on all 39 maps: for
every map, every tag in `movable()` except slot 0 (the builder needs slot 0
first) is replaced by its built tree. The trees are placed in reverse slot
order, first-fit into the freed space, so children come out in the
builder's depth-first order at new addresses. The rebuilt map then reads
back with a valid checksum, the same index and string table, every pinned
tag byte-identical at its address, every moved tag's **address-free tree**
(`read_tree`: element bytes with block addresses zeroed, children followed,
including shared ones) identical to the original, and every tag of the
groups `DecodedTag` supports (`bitm`, `scnr`, `matg`, `sbsp`, `mode`)
decoding to the same `Debug` text once addresses are masked (or failing
to decode in both maps). Results on
2026-11-17:

| Maps | Tags rebuilt | Notes |
|---|---|---|
| 19 (`00a`, `01a`, `03a`, `04a`, `05a`, `05b`, `07b`, `08a`, `ascension`, `beavercreek`, `burial_mounds`, `coagulation`, `colossus`, `cyclotron`, `foundation`, `lockout`, `midship`, `dune`, `elongation`) | every movable tag | e.g. lockout 3,744/4,512, 05a 7,092/8,274 |
| 12 (`01b`, `03b`, `04b`, `06a`, `06b`, `07a`, `headlong`, `zanzibar`, `containment`, `warlock`, `deltatap`, `backwash`) | movable tags without shared arrays | copying shared arrays overflows the tag-memory bound in reverse order; e.g. headlong 2,817/4,913 |
| 8 (`08b`, `mainmenu`, `shared`, `single_player_shared`, `waterworks`, `turf`, `gemini`, `triplicate`) | every movable tag, with `TagSet::check_tag_memory = false` | these sit at the bound (the bound is the largest retail map of the type), so any padding overflows; checked offline only |

Across all maps, 0 to 4 rebuilt tags per map landed back at their old
address by chance. No tree and no decoder result differed on any map.

instances, or a block the inference missed (all its instances agree on
nothing), so bytes past it are not reached. These cases are listed per
place by `H2_SCHEMA_WHY=1`.

Unit tests (`cargo test -p tags schema`), on an invented map: blocks, data
references, tag references, datums and string IDs are inferred; the text
form round-trips; tags move and read back identical; an undescribed
pointer and a missing block field each keep a tag pinned.

## Open

- **Transplant** (copying a tag graph between maps) is not done. `remap`
  is written but untested. Raw-resource pointers are not inferred yet, so
  a transplanted tag's local raw data (geometry, sound, pixels) would point
  at the wrong file offsets. Shared-map pointers (`shared.map`,
  `single_player_shared.map`) stay valid.
- **Deduplicating shared arrays** in the builder would stop built trees
  growing. Today they are copied into each tag that uses them.
- The remaining groups above, raw pointers, and BSP-region tags (`sbsp`,
  `ltmp`, which need the builder's BSP sections).
- Whether the engine accepts moved tags, depth-first child order and
  copied shared blocks is untested in game.
- Ambiguous fields are not marked unknown in the file. The per-tag check
  stands in for that. A new map whose tags put an address in such a field
  will be refused, not mis-relocated.
